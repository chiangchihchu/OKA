AWS API 呼叫端點與選型指南：

AWS 目前提供兩組推論端點，選型時需特別注意您的程式碼框架相容性：
1. 傳統端點 (bedrock-runtime)：支援 InvokeModel, Converse，涵蓋 Claude、Llama、Titan、Nova 等大部分傳統主力模型。
2. 相容端點 (bedrock-mantle)：支援 OpenAI 風格的 Chat Completions API。非常適合用來串接 DeepSeek、Gemma 3、MiniMax、Mistral Large 3、Kimi、Qwen3 等新引進的開源/非美系模型，讓現有程式碼無縫遷移。

1. 報價高度趨同 (Convergence)

在 PAYG (按量計費) 的 Serverless 模式下，三大平台對於同款模型（如 Llama 3.3 或 Mistral）的 API 報價幾乎是一模一樣的，不存在利用單純 API 價差來套利的空間。供應商間比拼的已非「表定單價」，而是「誰能先上架最新模型」。

2. 隱性成本陷阱 (Hidden Costs)

跨雲端比較時，真正的價差在於**網路傳輸費**與**吞吐量保障 (PT)**。
如果您的應用在 AWS，卻去呼叫 Azure 的第三方模型 API，跨區與跨網的 Data Transfer Out (DTO) 費用可能會吃掉所有利潤。強烈建議「應用在哪個雲，就用那個雲的 LLM」。

3. 企業採購與消耗承諾

選擇模型的重點在於您的**雲端消耗承諾 (EDP/MACC)**。
例如：AWS 的 Claude 費用可以直接折抵 AWS 企業合約額度；但如果在 Azure 上透過 Marketplace 購買 Claude，通常**無法**計入微軟的 MACC (Microsoft Azure Consumption Commitment) 額度中。
